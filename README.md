# Study

HTML / CSS / JavaScript のみで動く学習アプリ。サーバー不要（`index.html` をブラウザで開くだけ）。
ジョブごとの FF10 風スフィア盤を進めながら、マスの問題に答えてアビリティを覚えていく。

## 使い方

- PC: `index.html` をブラウザで開く
- iPhone: 静的ホスティング（GitHub Pages など）に置いて Safari で開き、共有メニューから「ホーム画面に追加」
  - iOS はローカルの HTML ファイルを直接実行しにくいため、ホスティングを推奨
- 学習記録は端末ごとの localStorage に保存。端末間の移行は「データ管理」のバックアップ / 復元で行う

## 構成

```
index.html
plugins.js            読み込むプラグインの一覧（追加時はここに1行足す）
css/style.css
js/core.js            プラグイン登録・回答の記録・保存
js/app.js             共通の画面部品、トップ（ジョブ選択）、データ管理
js/sphere.js          スフィア盤と熟練度
js/challenge.js       マスを開くラーニング（出題・制限時間・クリア判定）
jobs/*.js             ジョブ（スフィア盤）の定義
questions/<ジョブ>/   マスの問題
modes/quiz4.js        出題形式: 4択 / すべて選べ
modes/explain.js      出題形式: 記述して自己採点
```

## ジョブとスフィア盤

- ジョブ（`jobs/*.js`）ごとにスフィア盤が1枚ある。アビリティは攻撃・魔法・回復・補助の4系統
- マス = 10問のスキルラーニング（9割以上の正解でクリア）。アビリティのマスをすべてクリアすると、アビリティラーニング（20問、18問以上でクリア）に挑戦でき、クリアでアビリティを習得
- アビリティラーニングは3段構成: 最初の6問は早押し（正解したことのある問題を優先）、次はじっくり、最後の6問は★3の問題
- 同じ道（`group`）のアビリティは定義順に開く。`requires` は他の道の前提アビリティで、選ぶと前提元と点線が光る
- 上級ジョブ（`tier: 'advanced'`）は、`requires` のジョブをすべて熟練度★4以上にすると挑戦できる

### 熟練度

全アビリティをラーニングすると熟練度が1つ上がり、スフィア盤の次の周回に進む。2周目以降は全マスが開放され、次のレベルの形式で出題される。

| 熟練度 | 状態 | 形式 | 問題 |
|---|---|---|---|
| ☆☆☆☆★ Lv1 | 知っている | 4択 | 共通の問題 |
| ☆☆☆★★ Lv2 | 見極められる | 長文の「すべて選べ」 | 共通の問題のうち `hard` があるもの |
| ☆☆★★★ Lv3 | 理由を説明できる | 答えと理由の二段階 | `level: 3` で登録（形式は準備中） |
| ☆★★★★ Lv4 | 誤りを見抜ける | 誤りを見つける | `level: 4` で登録（形式は準備中） |
| ★★★★★ Lv5 | 自分の言葉で語れる | 記述して自己採点 | 共通の問題 |

形式と制限時間は `js/challenge.js` の `LEVELS`、名前は `js/sphere.js` の `PROFICIENCY` で決めている。

### 問題の共有

マスの問題が10問（アビリティは20問）に満たないときは、他のマスの問題で補う。不正解 → 迷った の順に弱点を優先し、同じアビリティと前提アビリティの問題を先に使う。それ以外のアビリティからは答えたことのある問題だけを使う。

## マスの問題の追加

`questions/<ジョブ>/<アビリティ>.js` を作り、`plugins.js` の `questions` に追加する。

```js
StudyApp.registerQuestions({
  job: 'genai', ability: 'ml-basics', cell: 0,   // cell はアビリティ内のマスの番号（0 始まり）
  // level: 3,                                   // その熟練度専用の問題のときだけ指定（省略時は共通の問題）
  questions: [
    {
      id: 'mlb0-01',           // ジョブ内で一意。後から変えない
      type: 'choice',
      difficulty: 2,           // ★1〜3
      question: '問題文（`code` と **強調** が使える）',
      choices: ['選択肢0', '選択肢1', '選択肢2', '選択肢3'],
      answer: 0,               // 正解の index。表示時は毎回シャッフルされる
      explanations: ['各選択肢がなぜ正しい/誤りか', '', '', ''],
      point: '覚えるべき要点（1文）',
      hard: {                  // 熟練度 Lv2 で出題する「すべて選べ」版
        question: '長めの状況設定つきの問題文',
        choices: ['記述0', '記述1', '記述2', '記述3', '記述4'],
        answers: [0, 2],       // 選ぶべき記述の index（複数）
        explanations: ['各記述の解説', '', '', '', ''],
      },
    },
  ],
});
```

## 出題形式の追加

`modes/xxx.js` を作り、`plugins.js` の `modes` に追加し、`js/challenge.js` の `LEVELS` で使うレベルを指定する。

```js
StudyApp.registerMode({
  id: 'twotier',
  title: '二段階',
  supports: (q) => q.type === 'twotier',     // この形式で出題できる問題か
  passes: (grade) => grade !== 'wrong',      // 任意。正解として数える判定
  render(el, q, api) {
    // el に問題を描画する。StudyApp.ui.h / StudyApp.util.format が使える
    // api.job            出題中のジョブ
    // api.hard           「すべて選べ」版で出すか
    // api.onKey(fn)      キーボード操作のハンドラを登録
    // api.answered()     回答した瞬間に呼ぶ（早押しのタイマーを止める）
    // api.finish(grade)  回答完了。grade は 'confident' | 'unsure' | 'wrong'
    // StudyApp.ui.shareToAI(text, button)  外部 AI チャットへ渡す（スマホは共有シート、PC はコピー）
  },
});
```

## 組み込んでいる学習法

| 手法 | 実装 |
|---|---|
| 想起練習 | 解説は回答後にのみ表示 |
| 段階的に深める | 熟練度ごとに、選ぶ → 見極める → 理由を説明する → 誤りを見抜く → 自分の言葉で語る |
| 確信度評価 | 正解時に「確信あり / 迷った」を選択。迷った問題は弱点として扱う |
| 弱点の再出題 | 不正解・迷った問題を、問題の共有で優先して出す |
| 前提から順に | スフィア盤は前提アビリティから順に開く |
| 精緻化フィードバック | 全選択肢に正誤の理由、要点を表示 |
| 選択肢シャッフル | 位置での記憶を防止 |

## セキュリティ

閲覧者の端末にプログラムを仕込まれたり、データを持ち出されたりしないよう、次の設計にしている。利用者向けの説明はアプリのトップ下部「Security Policy」（`js/app.js` の `renderSecurity`）。内容を変えたら両方を合わせること。

| 対策 | 実装 |
|---|---|
| 外部依存なし | 外部ライブラリ・CDN・広告・アクセス解析・外部フォントを使わない。ビルドもパッケージも不要 |
| CSP | `index.html` の meta で `default-src 'none'`、スクリプト・スタイルは自サイトのみ、通信（`connect-src`）・埋め込み・フォーム送信は禁止、`base-uri 'none'` |
| インラインを使わない | インラインスクリプトなし。style 属性は CSP で止まるため `h()`・`s()` で CSSOM（`el.style.cssText`）経由で設定する |
| HTML の注入防止 | `innerHTML` に入れるのは `StudyApp.util.format`（全文をエスケープしてから `code`・`strong` だけ付与）を通した自前の問題データだけ |
| 保存データの検証 | `js/core.js` の `sanitize` で、localStorage とバックアップを既知のキー・型・値だけで作り直す。`__proto__` などのキーや想定外の値は捨てる（GitHub Pages では同じユーザーの他リポジトリと保存領域を共有するため） |
| ファイル | 配るのはバックアップの JSON だけ。復元は JSON として読み、500万文字を超えるものは拒否する |
| 外部への受け渡し | 「AI に質問する」は利用者がボタンを押したときだけ、共有シート / クリップボードに文字列を渡す |
| リファラ | `no-referrer` |
| 問題の出どころ | 一般に公開されている情報と一般的な知識をもとに作成。研修資料などの会社の資産や、企業の機密情報は使用しない |

GitHub Pages ではレスポンスヘッダーを設定できないため、`frame-ancestors` などヘッダーでしか効かない指定は使えない。公開内容の改ざん防止は、リポジトリ所有者のアカウント管理に依存する（2段階認証とパスキー認証を有効化済み）。
